## Coverage rules

- Nationwide product intent is not model coverage evidence. Geographic/crop/year coverage must be established per feature.
- Coverage APIs and user interfaces should report evidence-backed `supported`, `unsupported`, `unknown`, or `unavailable` states.
- A file on disk, a registry row, a successful deserialization, a smoke prediction, or retrospective metric does not independently establish validity, safety, reliability, or production readiness.
- The current repository status values must not be upgraded through architecture documentation. Any status transition requires a separately reviewed evidence package and release approval.
- Do not derive a future-risk endpoint from existing risk CSVs or the `NOT READY` classifier.
