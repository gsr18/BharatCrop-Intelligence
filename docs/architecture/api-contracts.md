# BharatCrop Intelligence: API Contracts

**Status:** Every route and schema below is **proposed, not implemented or tested**.  
**Base path:** `/api/v1`  
**Authentication:** Protected routes require a verified authenticated principal from an identity solution not yet selected. Exact token/session transport is undecided. Backend authorization is mandatory; frontend visibility is not an access control.

## Contract-wide conventions

- JSON request/response bodies use UTF-8. Unknown fields should be rejected on security-sensitive inputs; schemas must be versioned and documented.
- Timestamps are RFC 3339/ISO 8601 instants in UTC with offset (`Z`). Date-only values use `YYYY-MM-DD`; agricultural year/season semantics must be explicit, not inferred from a local timestamp.
- Use stable opaque identifiers. Do not expose database sequence keys. Location identifiers must refer to a verified vocabulary/version; until one is approved, clients cannot assume district-name matching proves equivalence.
- Numeric agricultural measures must identify units, period, geography, and whether values are observed, estimated, or ranked. Yield units are not sufficiently established by this specification and must be fixed from verified source/model contracts before enabling a yield route.
- Paginated list endpoints use `page_size` (bounded by server policy) and opaque `page_token`; responses return `items`, `next_page_token` (nullable), and `page_size`. Stable ordering is required. Exact maximum page size is an implementation decision.
- Responses include `request_id` (correlation ID). Accept a validated caller `X-Request-ID` or generate one; never use it as an authorization credential. Return it in the response and sanitized logs.
- State-changing requests that clients may safely retry support `Idempotency-Key`. Scope keys to principal, method, and route; reject reuse with a different payload. Retention period is an implementation policy decision. Do not make inherently non-idempotent operations retryable without this mechanism.
- Use optimistic concurrency (`If-Match`/ETag or an explicit version) for mutable resources where concurrent edits could overwrite consent, farm, case, or knowledge state.
- Every error uses the common envelope below. Errors do not include stack traces, SQL, secrets, provider payloads, or sensitive resource content.
- API contracts never promise nationwide coverage or an existing provider/model version. Capability and coverage responses are dynamic evidence-backed statuses.

## Common error envelope

```json
{
  "error": {
    "code": "stable_machine_code",
    "message": "Localized, non-sensitive explanation",
    "details": [],
    "request_id": "correlation-id"
  }
}
```

This is a shape proposal, not a sample of a real response. `details` may identify safe field-level validation errors; it must not leak another user's resource existence where concealment is required.

Common HTTP/error codes: `400` malformed request; `401` unauthenticated/invalid identity; `403` authenticated but not permitted; `404` absent or intentionally concealed resource; `409` state/version/idempotency conflict; `410` expired/revoked resource where disclosure is safe; `413` body too large; `422` schema/semantic validation failure; `429` rate limit; `500` unexpected internal failure; `502` dependency response invalid; `503` temporarily unavailable; `504` dependency timeout. Stable codes include `validation_error`, `authentication_required`, `permission_denied`, `resource_not_found`, `consent_required`, `consent_expired`, `coverage_unavailable`, `feature_not_approved`, `model_unavailable`, `evidence_insufficient`, `idempotency_conflict`, `rate_limited`, and `dependency_unavailable` as appropriate.

## Authorization matrix

| Resource/action | Farmer | Agricultural expert | Administrator |
|---|---|---|---|
| Own account/preferences/farms/results/conversations | Allowed within self-service policy. | Own account/preferences; no farmer data by role alone. | Own account/preferences; no blanket access to farmer content. |
| Another farmer's farm/results/conversation | Denied unless the user is the resource owner. | Denied unless case assignment and current explicit consent/other documented basis cover the exact resource/action. | Denied by default; narrowly scoped documented operational/legal access only, logged and reviewed. |
| Expert case/review | Own cases and permitted reviews. | Assigned cases only while grant/basis is active; action scope enforced. | Case administration only for documented purpose; content access not implied by admin role. |
| Knowledge administration | No. | No, unless separately assigned a documented curation role (not assumed). | Dedicated permission, versioning, review and audit required. |
| Model status/release | No. | Only if separately designated model steward. | Only designated steward/reviewer; production approval requires evidence gate. |

The matrix is a proposed baseline; detailed role separation and legal basis remain subject to review.

## Endpoint release constraints

The presence of an endpoint in this proposal is not permission to expose the corresponding feature. In particular, `/predictions/yield` and `/rankings/crops` remain disabled until model/use gates pass; weather routes must use verified sources/coverage; risk-warning routes are intentionally absent; expert case reads require current scoped authorization; and assistant messages require an approved corpus/provider and citation validation.
